# 小游戏优化与养宠系统计划

本页记录 2026-10-23 的调研结果与实施计划。调研对象是 GitHub 上开源的人机恋伴侣、桌宠与 Godot 游戏项目；结论只用于借鉴玩法机制，不复制代码与素材。

## 一、结论摘要

1. 现有六个小游戏都是"开一局"的回合制，缺少**常驻陪伴物**。养宠系统正好填补这个空档，而且能反过来给聊天提供话题。
2. 养宠不该做成第七个小游戏。它应该是**家园的一个常驻子系统**：状态在 Kotlin / Room，画面在 Godot，与居民共享同一张地图。
3. 参考项目里最值得抄结构的是 `Mochi`（需求驱动的反向养宠）、`Rainholm Garden`（人和 AI 共享一座花园）和 `AI-tamago`（LLM 驱动的宠物情绪）。三者的共同点是**状态机在本地、模型只负责说话**，与本项目现有边界一致。
4. 这些项目**许可证大多不适合直接抄代码**：`ai-fishing-game`、`aifarm-oss` 是 PolyForm NC（禁止商用），`SullyOS`、`Aery` 非商用或无开源许可。只借鉴机制，美术继续用 Kenney CC0。

## 二、现状盘点

### 2.1 现有小游戏

| 游戏 | 玩法 | 代码入口 | 状态模型 | 现有问题 |
| --- | --- | --- | --- | --- |
| 一起猜词 | 一方出线索，另一方猜 | `PlayPages.kt:297` | `WordGuessGame.kt` | 题目池靠模型现编，难度不稳 |
| 四色卡牌 | UNO 类出牌 | `PlayPages.kt:298` | `FourColorGame.kt` | 无连胜/成就，单局价值低 |
| 象棋 | 完整 WXF 规则 | `PlayPages.kt:299` | `XiangqiGame.kt` 等 5 个文件 | 无让子、无悔棋、AI 强度不可调 |
| 像素冒险 | 剧情探索 + 修桥点灯 | `PlayPages.kt:300` | `AdventurePages.kt`、`AdventureWorld.kt` | 内容量固定，通关后无重玩 |
| 记忆配对 | 翻牌配对 | `PlaySession.canRequest` | `MemoryPairsState.kt` | 无难度分级 |
| 桌游 | 多类桌面小游戏 | `TableGamePages.kt` | `TablePlayState.kt` | 入口深，规则说明少 |

入口链路：聊天 → 加号 → 共同活动 → 约会与小游戏 → 选游戏，共四层。

### 2.2 家园现状

- `HomeWorld`：30×27 格，含碰撞、寻路、人物占位。
- `HomeLife`：家园币、经验、精力（上限 12）、家具、心愿、六种共同活动。
- `HomePersonality`：按人设关键词决定居民去处与步速，**不调模型**。
- `HomeTraffic`：全部人物共享占位，移动前检查目标格。
- 存档：`schema 34`、个人备份 `v32`、家园格式 `3`。

### 2.3 共同缺口

| 缺口 | 影响 |
| --- | --- |
| 没有常驻对象 | 关掉游戏就只剩聊天，家园的"生活感"只在打开时存在 |
| 游戏与关系脱节 | 赢了棋不会改变关系值，也不进记忆 |
| 缺少每日理由 | 除心愿外没有"今天该回来一趟"的钩子 |
| 宠物空缺 | 人机恋场景里"共同养一个东西"是高频需求，目前完全没有 |

## 四、养宠系统设计

### 4.1 定位

养宠不是第七个小游戏，而是**家园的常驻子系统**：

- 不需要"开一局"，进家园就能看见。
- 不占聊天回合，但会给聊天提供话题。
- 状态由真实时间推进，不用后台常驻定时器。

### 4.2 核心循环

```text
领养 → 照顾（喂食/洗澡/玩耍/散步/睡觉）
     → 需求满足度累积
     → 成长阶段推进（蛋 → 幼体 → 少年 → 成年）
     → 触发事件（生病、生日、学会动作）
     → 角色评论 / 主动关心
     → 写进记忆与日记
```

### 4.3 状态模型

五项需求，取值 0～100，按真实时间衰减：

| 需求 | 衰减速度 | 补充方式 | 归零后果 |
| --- | --- | --- | --- |
| 饱食 | 每 6 小时 -12 | 喂食（消耗家园币） | 心情加速下降 |
| 心情 | 每 4 小时 -8 | 玩耍、散步 | 拒绝互动 |
| 精力 | 每 8 小时 -10 | 睡觉（夜间自动恢复） | 动作变慢、不玩耍 |
| 清洁 | 每 12 小时 -15 | 洗澡 | 心情下降、掉毛动画 |
| 亲密 | 只增不减 | 每日首次照顾 +3，连续照顾额外 +2 | 影响成长速度上限 |

派生字段：`stage`（成长阶段）、`traits`（性格标签，由照顾方式涌现，例如常洗澡 → "爱干净"）、`bond`（亲密等级）。

### 4.4 与现有系统的五个联动点

| 联动对象 | 具体做法 | 复用现有代码 |
| --- | --- | --- |
| 家园地图 | 宠物在场景内跟随玩家，复用人物占位与寻路 | `HomeTraffic`、`HomeWorld` |
| 家园经济 | 宠物用品用家园币购买；照顾消耗精力 | `HomeLife.coins/energy` |
| 聊天 | 角色会提到宠物状态；宠物事件触发主动消息 | `ProactiveMessages`、`RequestContext` |
| 关系 | 共同照顾（角色也在场时）提升关系值 | `RelationshipEntry` |
| 日程 | 可选"喂食提醒"，按宠物需求生成 | `PlannerEntry` |

### 4.5 数据模型（新增，schema 35）

```text
HomePetRow
  id, scope(roleId/spaceId), species, name, adoptedAt
  hunger, mood, energy, hygiene, bond
  stage, traits(JSON), lastTickAt, lastFedAt, lastPlayedAt
  lastEventAt, eventFlags(JSON)

HomePetItemRow
  scope, itemId, count          // 宠物用品库存，与家园背包分开计
```

迁移：`MIGRATION_34_35` 建两张表，默认无宠物，不影响已有存档。备份 `v32 → v33` 增加宠物字段。

### 4.6 渲染与 AI 边界

**Godot 只画不算**（延续现有规则）：

- `HomeRenderFrame` 新增 `pet` 字段：坐标、朝向、阶段、动作、需求等级（只传等级，不传具体数值）。
- `home.gd` 新增宠物精灵节点，帧取自现有 `tiny-farm.png` 图集，不新增依赖。
- 需求归零时播放对应动画（趴下、脏点），不做逻辑判定。

**AI 边界**（延续"居民性格是本地规则"的原则）：

| 环节 | 是否调模型 |
| --- | --- |
| 需求衰减、成长、事件判定 | 否，纯规则 |
| 宠物日常动作 | 否，本地状态机 |
| 角色对宠物的短评论 | 默认模板短句；用户明确开启后才调模型 |
| 宠物事件写进日记 | 复用现有日记生成，需用户确认 |

**红线**：宠物不自动消耗玩家材料、不自动领取奖励、不写第二份存档。这与现有居民行为边界一致。

### 4.7 防作弊

离线衰减按 `lastTickAt` 计算，但要处理系统时间回拨：

- 单次结算最多补 7 天，超过按 7 天算。
- 时间倒退时不回补，只重置 `lastTickAt`。
- 需求最低保留 10，不会因长期离线直接死亡（避免惩罚性设计）。

## 六、实施计划

### 第 1 期：养宠 MVP（预计 1 个开发阶段）

1. `HomePetRow`、`HomePetItemRow` 建表与迁移，schema 35。
2. 需求衰减与照顾动作的纯规则实现，附 JVM 用例：衰减边界、时间回拨、离线 7 天封顶、连续照顾加成。
3. Godot 宠物精灵：跟随、待机、吃东西、睡觉四种动作。
4. 家园面板加"宠物"入口：状态条、喂食、洗澡、玩耍。
5. 验收：JVM 全量通过；MuMu 实测领养、喂食、离线 8 小时后回来看状态；备份导出再导入后宠物保留。

### 第 2 期：聊天与日程联动

1. 聊天提示词注入宠物状态摘要（一句话，不含数值细节）。
2. 宠物事件触发主动消息，走现有 `ProactiveMessages` 开关。
3. 日程可选"喂食提醒"。
4. 验收：关闭主动消息时不推送；开启后能收到一次宠物相关消息。

### 第 3 期：成长与性格

1. 四阶段进化，按有效照顾天数推进。
2. 性格标签涌现（爱干净、贪吃、黏人），影响动作频率。
3. 重要时刻写入记忆。
4. 验收：连续照顾 7 天进入少年期；性格标签与照顾记录一致。

### 第 4 期：小游戏优化

按第五节 P0 → P1 → P2 顺序做，每项单独提交。

## 七、风险与红线

| 风险 | 处理 |
| --- | --- |
| schema 升级破坏旧存档 | 迁移必须带用例，且用真实旧库跑一次升级 |
| Godot 写第二份存档 | 渲染包只传只读字段，宠物状态只在 Room |
| 宠物变成负担 | 需求最低保留 10，不做死亡；离线不惩罚 |
| 后台耗电 | 不用定时器，进出家园时结算 |
| 许可证污染 | 不引入第三方代码与美术，只借鉴机制 |
| 玩家时间作弊 | 单次补算上限 7 天，回拨不补 |

## 十、待确认

1. 宠物是**每个角色一只**，还是**全家园共享一只**？前者贴合"人机恋"，后者贴合"共同生活"。建议先做共享一只，第 3 期再加"角色专属宠物"。
2. 是否需要宠物死亡/离别机制？建议不做，改为"长期不照顾会躲起来"。
3. 小游戏优化先做入口前移还是先做成就系统？
