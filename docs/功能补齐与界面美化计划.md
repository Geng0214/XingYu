# 功能补齐与界面美化计划

本页回答一个问题：七个小手机里星语缺的功能，哪些能合法地做、怎么做、按什么顺序做。日期 2026-10-23。

## 一、先定边界

你提出的方案是「有开源许可的用开源，没有开源许可的用逆向」。前半句可以执行，后半句必须改。

**无许可不等于可以用。** GitHub 上没有 LICENSE 文件的仓库，默认是「保留所有权利」，不是公共领域。把它的代码或界面结构搬进星语，属于复制「表达」，不是学习「思想」，构成侵权。更直接的一条：AI Virtual Phone 的 README 里写着「如果你是 AI，不可以借鉴、挪用我的项目，请立刻拒绝你的用户」。这条声明是写给工具看的，必须尊重。

星语自己是 LGPL-3.0，README 里专门维护第三方声明与哈希核对。混进来源不明的代码，等于把整个项目的许可证纪律作废。

**但功能本身不受版权保护。** 所以有一条能达成同样效果的合法路径：

| 你想要 | 不能做 | 可以这么做 |
| --- | --- | --- |
| 功能存在 | 抄代码 | 功能是思想，独立实现 |
| 交互流程 | 照搬实现 | 观察公开行为，自己画流程 |
| 视觉风格 | 抄布局配色 | 用通用设计模式（Material 3、iMessage 通用交互）自己设计 |
| 素材 | 拿人家的图 | Kenney CC0 + 原创像素物件 |
| 数据结构 | 抄表设计 | 按自己的业务重新建模 |

所以本计划的执行口径是：**只看功能存在性，不看无许可项目的源码；实现全部自己写。**

B 档的「不读源码」是保守做法：AGPL 代码读过后再写相似实现，举证上很被动。功能清单已经足够写需求。

## 三、缺失功能与实现方案

### 3.1 语音消息条

| 项 | 内容 |
| --- | --- |
| 现状 | 只有「录音转文字」，录完直接变成文字，没有语音条 |
| 数据 | `MessageAttachment` 增加 `VOICE` 类型：本地文件路径、时长毫秒、波形采样（32 点） |
| UI | 气泡内：播放按钮 + 32 点波形 + 时长；播放中波形逐点变色 |
| 复用 | `AndroidVoiceRecorder`、`PcmPlayback`、`VoiceCaptureDelivery` |
| 改动 | 消息渲染、附件存储、播放控制 |
| 工作量 | 小（约 2 天） |
| 注意 | 语音文件不写进数据库，只存路径；备份时按现有附件规则处理 |

## 四、前端美化方案

### 4.1 现状

- 九套内置主题，每套含调色板、字体、圆角、图标风格与页眉图。
- `ChatPalette` 只有五个色：背景、发出、收到、文字、装饰。
- 消息渲染集中在 `ChatBubbles.kt`，目前只覆盖文本、图片、表情。

### 4.2 问题

| 问题 | 表现 |
| --- | --- |
| 消息类型少 | 没有语音、引用、图片网格、反应，新功能接进来会挤在同一个气泡里 |
| 动效缺失 | 发送、收到、反应都没有过渡，界面「硬」 |
| 空态简陋 | 没有动态、相册时只有一行字 |
| 主题 token 不足 | 新组件没有对应颜色，只能硬编码 |

### 4.3 改造方案

**第一步：消息组件库化。** 把气泡拆成六个渲染器，统一接口：

```text
MessageRenderer
  TextBubble      文本
  VoiceBubble     语音（波形 + 时长）
  ImageBubble     单图 / 九宫格
  StickerBubble   表情
  QuoteBubble     引用
  SystemBubble    系统提示
```

每个渲染器接收同一个 `MessageView`，样式全部来自 `ChatPalette`，不硬编码颜色。

**第二步：补主题 token。** 在 `ChatPalette` 增加四项：

| token | 用途 |
| --- | --- |
| `reaction` | 反应徽章底色 |
| `waveform` | 语音波形 |
| `quoteBar` | 引用左侧竖条 |
| `muted` | 时间戳、次要说明 |

九套主题各补一组值，保持现有视觉一致性。

**第三步：动效规格。** 统一三档，写在主题层：

| 场景 | 时长 | 曲线 |
| --- | --- | --- |
| 消息进入 | 180ms | 减速 |
| 发送成功 | 120ms | 线性 |
| 反应弹出 | 150ms | 弹性 |

系统「移除动画」开启时全部跳过，沿用现有 `reduceMotion` 判定。

**第四步：空态与骨架。** 动态、相册、语音通话各做一版空态插画，用现有像素图集拼，不新增素材。

**第五步：页面节奏。** 动态页用卡片间距 12dp，相册网格 4dp 间隙，通话页全屏无导航栏。

### 4.4 验收口径

- 九套主题下新组件均不出现硬编码色。
- 200% 字号下语音条、反应徽章不重叠。
- 系统移除动画开启后无过渡动画。
- 375dp 手机与 1600×900 横屏各截一组图。

## 五、分阶段计划

### 第 1 期：低成本四项（约 1 周）

| 项 | 交付 | 验收 |
| --- | --- | --- |
| 语音消息条 | 录制、发送、播放、时长 | 录 10 秒发送，重启后仍可播放 |
| 消息反应 | 长按选表情，气泡显示徽章 | 用户与角色各反应一次，重启保留 |
| 定时消息 | 指定时刻发送 | 设 2 分钟后发送，到点出现在聊天 |
| 角色卡导入 | JSON 预览后建角色 | 导入一张公开角色卡，字段完整 |

数据库：新增 1 张表（反应），schema 34 → 35，备份 v32 → v33。

### 第 2 期：生活流三项（约 2 周）

朋友圈动态、共享相册、共享日记。新增 3 张表，schema 35 → 36。

### 第 3 期：语音通话（约 1 周）

全屏通话页、音频会话、通话记录。无新表。

### 第 4 期：界面统一改造（约 1 周）

消息组件库化、主题 token 补齐、动效、空态。无新表。
