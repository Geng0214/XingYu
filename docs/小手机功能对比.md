# 小手机功能对比

本页把 2026-10-23 调研的七个小手机项目与星语当前功能逐项对照，用于决定补什么、不补什么。功能判断依据是各项目 README 与星语源码，不是宣传语。

## 一、先看结论

1. **星语在「陪伴深度」上不落后，在「生活流」上明显缺失。** 家园、日程、加密备份、隐私锁、共同观看这些，七个小手机一个都没有；但朋友圈、共享相册、语音通话这类"日常感"功能，星语全缺。
2. **七家里只有 ZeroChat（MIT）可以真正借鉴代码。** AI Virtual Phone 作者在 README 里明确要求 AI 不得借鉴或挪用其项目；柚月小手机禁止二改与抄袭；Aery 无开源许可；SullyOS 非商用；float-Yyk 与赴约是 AGPLv3，衍生需同样开源。**其余六家只能看功能思路，不能抄实现。**
3. **最值得补的三项**：朋友圈式动态、共享相册、语音通话。这三项都能复用星语现有的图片、语音和主动消息管线，改动集中在 UI 与数据表，不碰核心规则。
4. **最不值得补的三项**：3D 世界、应用市场 SDK、转账红包。前两个是另一个量级的工程，第三个涉及支付合规。

## 二、逐项对比

图例：`有` = 已实现可用；`部分` = 有相近能力但形态不同；`无` = 没有。

### 2.1 聊天与消息

| 功能 | 星语 | 谁有 | 差距与建议 |
| --- | --- | --- | --- |
| 私聊 | 有 | 全部 | 无差距 |
| 多角色群聊 | 有 | float、AVP、ZeroChat、Aery | 星语已有 AI 之间接话，缺"围观群/幕后导演"这类控制 |
| 角色人设 | 有 | 全部 | 无差距 |
| 世界书 | 有 | AVP、ZeroChat | 无差距 |
| 长期记忆 | 有（提取 + 召回） | ZeroChat、赴约（三层） | 赴约的三层记忆可参考分层命名，机制不必改 |
| 图片消息 | 有 | 全部 | 缺多图成组发送与叠卡浏览 |
| 表情包 | 有 | ZeroChat（按情绪自动发） | 可补"情绪触发自动选包" |
| 语音消息条 | 无 | AVP、float | 星语只有录音转文字，**建议补** |
| 语音通话 | 无 | 柚月（视频）、赴约（中断式语音） | **建议补**，复用现有语音服务 |
| 视频通话 | 无 | 柚月 | 成本高，暂不补 |
| 消息反应（Tapback） | 无 | float | 成本低、日常感强，**建议补** |
| 引用回复 | 部分 | float | 星语有引用，缺语音/图片引用预览 |
| 分段发送 | 部分 | ZeroChat | 星语按段落存，缺打字节奏 |
| 定时消息 | 无 | AVP、ZeroChat | 与现有主动消息共用调度，**建议补** |
| 转账红包卡片 | 无 | AVP | 涉及支付合规，不补 |
| 内心独白 | 无 | Aery | 可作为聊天页的"心声"气泡，中等成本 |

## 三、小手机独有优势排行

按"对星语的边际价值 ÷ 实现成本"排序：

| 排名 | 功能 | 代表项目 | 星语现状 | 成本 | 建议 |
| --- | --- | --- | --- | --- | --- |
| 1 | 朋友圈式动态流 | ZeroChat、float | 无 | 中 | 先做，接主动消息调度 |
| 2 | 共享相册 | float | 无 | 中 | 复用图片存储，加相册表 |
| 3 | 语音消息条 | AVP、float | 无 | 低 | 录音已有，加播放与气泡 |
| 4 | 消息反应 | float | 无 | 低 | 长按菜单加表情 |
| 5 | 定时消息 | ZeroChat | 无 | 低 | 复用主动消息调度 |
| 6 | 角色卡导入 | AVP | 无 | 低 | 解析 JSON，映射到现有角色表 |
| 7 | 语音通话 | 赴约、柚月 | 无 | 中 | 复用语音服务，加通话状态 |
| 8 | 共享日记 | SullyOS | 部分 | 中 | 日记加"共同"类型 |
| 9 | 共同画画 | float | 无 | 高 | P2 |
| 10 | 3D 世界 | AVP | 无 | 极高 | 不做 |

## 四、许可证与借鉴边界

这一节比功能表更重要。星语是 LGPL-3.0，混入其他许可的代码会产生分发义务。

| 项目 | 许可证 | 能做什么 | 不能做什么 |
| --- | --- | --- | --- |
| ZeroChat | MIT | 可读代码、可移植实现，保留版权声明 | 去掉原作者声明 |
| float-Yyk | AGPLv3 | 可读代码 | 直接移植会让整个应用适用 AGPL |
| AI Virtual Phone | AGPLv3 + 作者明确声明 | 只能了解功能存在 | **作者要求 AI 不得借鉴或挪用其项目，尊重该声明** |
| 柚月小手机 | 未声明，保留所有权利 | 只能了解功能存在 | 禁止二改、禁止抄袭 UI 与逻辑 |
| SullyOS | 非商用 | 只能了解功能存在 | 商用场景不可用 |
| Aery | 无开源许可 | 只能了解功能存在 | 不可复制任何部分 |
| 赴约 | AGPL-3.0 | 可读代码 | 移植需同样开源 |

**执行口径**：功能列表可以看，交互可以自己想，**代码与素材一律自己写**。星语现有的 Kenney CC0 图集与原创像素物件继续作为唯一美术来源。

## 五、建议的补充顺序

### 第一批（低成本，补日常感）

1. 语音消息条：录音已有，加播放按钮与波形。
2. 消息反应：长按消息选表情，存进消息表。
3. 定时消息：在主动消息调度上加"指定时刻"。
4. 角色卡导入：支持 SillyTavern 的 JSON 角色卡。

### 第二批（中等成本，补生活流）

5. 朋友圈式动态：角色按作息发动态，支持点赞评论，聊天中可引用。
6. 共享相册：聊天图片、生成图、上传图统一归档，可按角色分享。
7. 共享日记：日记增加"共同"类型，角色可以续写。

### 第三批（按需）

8. 语音通话：复用现有语音服务，加通话中状态与挂断。
9. 共同画画：独立画板，P2。
10. 记忆可视化：把现有记忆列表做成关系图。

## 六、不做的部分

| 功能 | 原因 |
| --- | --- |
| 3D 世界 | 与现有 Godot 2D 管线冲突，工程量数倍于全部小游戏 |
| 应用市场 SDK | 星语已有 MCP/ToolPkg，再做一套是重复建设 |
| 转账红包 | 涉及支付合规与真实资金，超出个人项目边界 |
| 微博热搜 | 依赖外部接口，随时可能失效 |
| 论坛 | 与朋友圈重叠，且需要内容治理 |
| TRPG | 与现有回合制小游戏重叠 |
