# 项目计划与当前进度

此页记录项目目标、当前进度和最近两个阶段。E15 及更早的完成记录见[历史阶段](历史阶段.md)；目录入口见[项目导航](README.md)，逐项结果见根目录 `../evidence/` 阶段记录。

## 项目目标

在保留 Operit 插件能力的基础上，逐步把本应用做成可个性化的陪伴小手机。当前产品方向由用户提供的功能参考和开源项目调研整理而来；它们是设计参考，不代表功能已实现或许可证允许复制代码与素材。

- 日常陪伴：私聊与群聊、角色设定、世界书、记忆、日记、关系、日程、纪念日和可控主动消息。
- 多媒体和共同活动：图片、文件、表情、生图、语音、共读、听歌、视频、剧情和小游戏；沿用现有功能记录，不复制同一份业务数据。
- 个性化空间：应用内陪伴桌面、共享家园、主题、角色与关系设置；个人记录按角色隔离，家园世界由用户和全部居民共同经营，桌面和主题预览后保存。
- 扩展与权限：继续维护 ToolPkg/MCP 扩展；服务和设备能力按角色或动作单独授权，执行前说明目标与请求，操作后可撤权并查看实际结果。
- 数据与帮助：加密备份、兼容升级、使用说明、可检索帮助和脱敏诊断；云服务保持可选，费用和数据发送范围在操作前说明。

不伪装系统 Launcher，不宣称模型有真实情绪，不把模拟结果说成真实交易或设备操作。主题文件不执行脚本，导入内容先预览；复用外部代码或素材前，逐项确认许可证和分发义务。

3. 新 `CompanionHomeUi`：雨窗场景、领养卡、照顾面板、共同手账和“院子”入口；沿用现有 `HomeUi` 的 pending、错误与重试。
4. 聊天回流：把宠物一句话摘要放进 `RequestContext`，只读、不生成数值；主动消息与日程提醒留到下一阶段。
5. 验证：新增 JVM 用例；经用户授权后运行全量 JVM / Release 构建；MuMu 验证领养、照顾、交接、重启和格式 3 升级。

## 已完成：E17 功能补齐第 1 期（代码与构建，部分设备项待验）

按[功能补齐与界面美化计划](功能补齐与界面美化计划.md)的第 1 期实施，完成语音消息条、消息反应、定时消息和角色卡导入，并补数据库与备份迁移。

1. 语音消息条：录音预览可直接发送语音；气泡显示播放、32 点波形和时长，数据保存在 `message_voices`，重启后仍可播放。发送语音会触发一次角色回复，模型只收到语音时长占位，不收到原始录音。
2. 消息反应：长按消息选择表情，每侧最多 3 个；角色回复完成后按消息 ID 在本机生成固定反应，不额外调用模型。反应保存在 `message_reactions`。
3. 定时消息：角色资料页可安排固定文本或让角色生成；固定文本到点直接写入聊天，不联网；生成模式到点调用所选模型。列表显示待发送／已发送／已取消／失败。当前未接入主动消息的免打扰和每日上限，到点也不单独发系统通知。
4. 角色卡导入：角色管理页支持 SillyTavern V1/V2 JSON，导入前预览角色名、人设、开场白和世界书；确认后创建独立角色，世界书条目默认关闭，备选开场白和未知字段不写入。
5. 数据升级：数据库 schema 34→35，个人备份 v32→v33；新增 `VoiceReactionScheduleMigration`、schema 35 导出和 22 个 JVM 用例。备份现在保存用户发送的语音条、消息反应和定时消息记录。
6. 验证：599 项全量 JVM 检查通过（84 个测试类，失败、错误、跳过均为 0）；Release 构建成功。MuMu Android 15 覆盖安装 0.39.0→0.40.0，原角色和聊天保留；反应冷启动保留、固定文本定时消息到点出现、角色卡预览／创建／删除、200% 字号和语音预览已核对。测试角色、聊天测试消息和反应已清理，定时消息历史保留一条「已发送」记录；系统字号已恢复。
7. 未验收：语音发送后的气泡播放与重启保留、角色生成定时消息、v32→v33 设备备份恢复、通知、竖屏 375dp、TalkBack、真机和在线模型。结果见 [E17 验收](../evidence/E17_FEATURE_PHASE1/validation.md)，交付包见 `output/local-companion-0.40.0.apk`。
