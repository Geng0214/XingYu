# E1 第三段：模型工具回合与应用管理界面

日期：2026-09-20。状态：远程 MCP 开发链路与宿主验证完成，ToolPkg 和 Android 验收未完成。开发版本 0.5.0/code 5/schema 5；本次内部签名包用于构建检查，公开交付仍为 0.4.0。

## 已实现行为

- 设置 → 扩展与工具：添加、编辑、删除 HTTPS MCP Streamable HTTP 服务；独立加密 Bearer 凭据或明确匿名连接；完整地址确认、超时、可取消连接测试、工具列表、启停。更换地址必须重新填写凭据。
- 角色编辑页或扩展页选择该角色可使用的工具，最多 32 个，描述与定义合计最多 65536 字符；复制角色不复制授权。保存服务、停用、刷新工具或删除服务在协调器锁内停止当前请求，再修改授权，不能与新发送穿插执行。
- 聊天进入实际模型工具循环：先积累 OpenAI 兼容 SSE 的工具参数，收到完整 tool_calls 结束事件后验证整批调用；只有冻结到本请求的工具可执行。工具名称使用服务身份生成的稳定别名避免冲突，描述保留真实工具名。
- 每次调用显示所属角色、完整 MCP 地址和参数，单次允许或拒绝。确认票据不能重复或跨请求使用；取消及进程中断不会恢复确认或重放调用。
- 调用结果按对应 tool_call_id 回传本次模型，再接收最终回复。一次请求最多 8 次调用，不自动重试外部动作；取消后迟到结果不能开始下一轮模型请求。工具声明错误作为结果交回模型，网络/权限/协议错误明确停止。
- 聊天可查看所属会话的加密调用记录和状态；切换角色、会话、关闭或删除对话立即清除旧调用视图。一次保持一个生成任务，原停止按钮同时取消正在等待确认或执行的工具。
- 普通角色未授权工具时仍不发送 tools。沿用冻结角色、模型、空间和配置快照；不把另一角色的上下文或 MCP 凭据交给模型。仅显式返回的 reasoning_content 在本次回合内存中回传兼容接口，不展示、不落盘；真实兼容提供商仍待验。

流式调用与回传格式依据 [OpenAI 官方 function calling 文档](https://developers.openai.com/api/docs/guides/function-calling)。旧 function_call 格式及旧 MCP SSE 传输未在本段实现，明确拒绝或列为待兼容。

## 本次发现及修复

首次离线 release 构建发现 kotlin-logging-android 7.0.14 发布变体未缓存。旧依赖清单只遍历 ResolutionResult，可能遗漏未解析节点；旧 170 坐标不能视为完整验证。修复为先强制解析 runtime 文件，再生成清单，并补齐缺失变体及显式 NOP 日志实现。当前 172 坐标已完整解析、重新生成声明，最终构建可离线完成。旧阶段测试记录保留，以上为依赖完整性的勘误。

核对日志库字节码：默认选择 SLF4J，只有设置 kotlin-logging-to-android-native 属性才选择 Android 日志；当前代码没有设置该属性。Android 测试会核对实际后端。新增日志测试最初缺少测试编译路径中的 kotlin-logging 声明，补齐测试依赖后通过；没有关闭测试或删除断言。
