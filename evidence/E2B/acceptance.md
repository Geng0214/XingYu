# E2 第二项：个人加密备份

日期：2026-09-20。目标 0.7.0/code 7/schema 6。功能开发完成、设备验收待补齐。0.6.0 隐私锁证据位于 evidence/E2；本目录保留备份交付记录，不覆盖历史结果。

## 实现范围

全部 12 张业务表与可选 API Key 的事务快照；范围预览、双次口令确认、32 MiB/10 万条限制、PBKDF2-HMAC-SHA256 与 AES-GCM、系统文件保存与回读比对。恢复验证版本、列类型、唯一键、角色空间/会话/请求归属、图片与插件完整性，预览后追加独立身份副本，原记录不覆盖。导入插件只静态验证并停用授权，不执行脚本或出网。

目标设备独立加密新凭据并绑定原目的地；不含 Key 时不给新模型借用本机凭据。本机数据库密钥和隐私锁设置保持不变。SQL 事务失败或提交前取消清除新增数据与暂存 Key，提交收尾避免协程取消破坏已提交引用。明确记录进程异常终止可能留下未引用加密凭据，不虚构跨文件原子性。

## 宿主与构建验证

BackupTest 使用实际 JCA 加密、编码、验证和重映射实现，覆盖中文/emoji、随机性、错误口令、篡改头/密文/标签、截断/尾随数据、未知版本、非法 UTF-8、恶意长度、跨空间/凭据地址篡改、重复身份与请求冲突、大小限制、真实时间插件包静态验证、完整 Room schema 列映射。50 次重映射检查 A/B 标记不串入其他角色及权限关闭。

构建前运行既有测试和新增测试；最终通过数量、源码提交、干净构建、签名、APK 与 ZIP 哈希以本目录测试结果和 delivery.json 为准。静态 APK 检查不能证明设备落盘、系统文件提供方或跨手机恢复已通过。

人工待验：系统文件选择器保存和回读、取消与提供方错误、开启隐私锁后的文件往返、旋转/进程终止、低内存及大备份、错误口令、两台 ARM64 手机之间的含 Key 与不含 Key 恢复、恢复后的真实模型与 MCP 连接。仅在对应数据可打开时追加恢复，不能把备份当成丢失本机系统密钥后的修复工具。

M1/M2/E1/E2 隐私锁未完成的设备、真实服务商、实际 MCP、模板跨设备与三人观察仍为 NOT_RUN。整个 E2 与总计划未完成；下一项继续用户面具、世界书和其他设定功能。
