# E5 04b 录放音绑定验证

状态：未发布的录放音接入点。04b 整项尚未完成；当前 ViewModel 没有传入通信绑定，最新交付仍是 0.32.0。本次未修改包名、签名、版本、数据库、备份、Manifest、依赖或模块，也没有重新打包 APK 或源码归档。

## 已实现

录音和播放接受本轮明确的输入、输出身份和路由租约检查。真实 Android 适配代码设置首选设备后，继续查询实际路由；接受首选设备不能代替实际确认。API 36 的多输出列表必须仅包含所选设备。确认前播放仅提交静音，录音不保存采样，并额外丢弃完整原生缓冲中的旧输入数据。确认后的设备丢失保持失效，旧回调只能停止旧 AudioRecord/AudioTrack；资源关闭错误仍尝试释放原生音频对象。

通信路径使用 VOICE_COMMUNICATION 属性且复用整轮焦点。SCO 输入采用 8 kHz 单声道 PCM16，转换成语音识别服务的 16 kHz；合成服务的 24 kHz PCM16 经窗函数低通转换成 16 kHz 通话输出。转换不改写输入数组，输出长度按实际采样率计算；转换失败与录音交付失败擦除相应结果数组。

## 验证边界

十项新增 JVM 用例运行实际路由判定和音频转换代码：错误 ID/类型、未确认、多个输出、20 次断连/重连/旧状态操作、移除与焦点失效、采样时长、正负幅值、静音、单采样、限幅、4 kHz 保留、10 kHz 混叠抑制、非法/超限负载、转换取消与路由丢失。宿主波形测试不是蓝牙音质验收，路由状态测试没有执行 AudioManager、AudioRecord 或 AudioTrack。

全套 300 项 JVM 测试通过，无失败/错误/跳过；Android 测试代码编译通过，未在设备运行。Release Lint 为 0 错误、60 警告、1 提示。最终验证构建 20 秒、75 项任务，10 项执行、65 项已是最新。源码提交与文件哈希见 [机器记录](validation.json)，命令输出见 [最终验证日志](build-validation-final.log)。没有运行 clean/签名打包，不用编译成功冒充设备测试。

前一次验证有一个新测试失败，见 [首次验证日志](build-validation.log)：测试要求满幅阶跃附近的每个采样都高于 30,000，未允许窗函数滤波的正常振铃。改为检查该区域保持正确符号且过冲饱和到正负边界，能够识别直接缩窄整数造成的溢出；原时长、频率保留与混叠抑制断言不变，没有为此修改生产转换算法。随后全套验证通过。

## 下一步和未验项目

- 在 ViewModel 与设备选择界面接通整轮路由租约，角色切换、暂停、结束、重开和隐私锁等待旧录放音结束；按键录音/朗读以及媒体拔出策略仍需接线。
- Android 输入缓冲清除、焦点竞争、回调注销、拔插耳机时可能的短暂转路、API 36 并行输出、8/16/24 kHz 实际录放音、蓝牙重连、来电、20 轮连续语音、覆盖安装和双真实语音服务均为 NOT_RUN。系统路由变化与回调之间存在延迟，不能据本轮单元测试声称无音频泄露或真机验收通过。
