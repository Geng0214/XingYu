# E5 音频路由 04a 核心验证

状态：路由控制器与 API 31+ 原生适配器已完成核心开发，产品接线和设备验收未完成。没有新 APK，0.32.0 及其交付清单保持不变；未增加 Manifest 权限、模块、依赖、数据库字段或备份格式。

## 已实现与已执行

`CommunicationRoutes` 等待指定设备实际成为当前通信设备才开始任务。系统拒绝、设备消失或最长 30 秒未确认都结束处理，不自动选择其他设备。选择确认后的一次断连立即使租约失效；重新连接不能抹除失效状态。结构化协程先取消并等待任务的 finally 完成，再关闭路由连接。取消恰好发生于平台资源交付之间时仍能回收本次资源；旧连接回调只影响旧状态。

七项新增 JVM 用例运行上述生产控制器，平台端口由测试模拟：异步确认、错误设备、受理拒绝、选择超时、焦点丢失、20 次断连重连/旧回调、单租约互斥、等待录放音清理、获取资源时取消、调用者超时保持取消语义及关闭失败报错。全套 290 项测试通过，无失败/错误/跳过。

Android 实现调用真实 API 31+ 设备目录、通信设备选择与监听、通信模式及焦点。安装失败会撤销已经注册的资源；清理中的单项异常不会阻止其他清理，释放焦点失败也会报错并阻止同一适配器继续申请。设备标签不进入日志、数据库或模型请求。原生方法目前只有编译和 Lint 证据；不存在模拟端口证明真实蓝牙已通过的结论。

最终源码提交、文件哈希、测试数和 Lint 状态见 [机器记录](validation.json)；命令与最终结果见 [验证构建](build-validation.log)。已编译现有 Android 测试，但没有连接安卓设备，未运行原生路由测试，也没有 clean/签名构建或新源码包。

## 未完成和下一步

API 26～30 的 SCO/旧路由路径、MODIFY_AUDIO_SETTINGS 等实际接线权限、设备选择界面、录音器 VOICE_COMMUNICATION 与播放器通话属性、持续语音整轮焦点、实际输入/输出设备观察、按键录音与单次朗读以及媒体拔出策略仍待开发。现在的产品不会调用新适配器，因此不能宣称 APK 已具备设备选择或蓝牙通话。

实机设备枚举/选择/拒绝/超时、HFP/BLE/有线/USB/听筒、录放音质量、来电焦点、拔插重连、20 轮真实连续语音、锁定/旋转/后台和两个真实服务商均为 NOT_RUN。低版本兼容性仍是最终要求，不能用版本拒绝结束本项。阶段索引见[项目导航](../../docs/README.md)。

设计依据为 [Android 自管理音频指南](https://developer.android.com/develop/connectivity/bluetooth/ble-audio/audio-manager) 和 [AudioManager](https://developer.android.com/reference/android/media/AudioManager#setCommunicationDevice(android.media.AudioDeviceInfo))。接口方法名和编译成功不等于实际路由及隐私验收。
