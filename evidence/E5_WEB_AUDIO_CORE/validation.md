# E5/04c 网页音频接收侧与可行性验证

2026-09-21 未发布开发，基线为 `d57ab5ab`。平台与浏览器调查排除了用 AudioPlaybackConfiguration 或预期路由查询冒充 WebView 实际输出的路线，并在官方公开样本上验证可读取非零 Web Audio 采样，见 [浏览器实验](browser-audio-probe.json) 与[项目导航](../../docs/README.md)。测试页已暂停、关闭 AudioContext 并关闭，没有保留对用户浏览器页面的改动。

新增接收协议、流协调器及原生 PCM 输出模块。JSON 最大 8192 字符，复用 StrictJson 校验语法、重复键和嵌套上限，只读明确字段。音频固定每包 1024 帧双声道 16 位数据；队列最多 8 包。代际递增、每代包序号连续、采样率在 state 时冻结。暂停清除待播队列，旧代数据忽略，错误来源、子框架、当前文档不符、未知字段或超限数据均拒绝；页面没有获得应用配置、文件或工具能力。

原生音轨先提交静音并确认自身实际设备。暂停/定位后释放旧音轨，每个新音轨单独等待确认，不能复用会话之前的 ready 标志；API 36 检查全部输出。原生写入完成且包仍属于当前代际才发送确认；消费结束、取消和未消费的队列按所有权擦除。原生模块尚未执行，不能据此声称耳机或暂停已工作。

本轮尚未接入 BilibiliPlayer、全局静音、AudioWorklet 或消息监听，未增加 WebKit 依赖。现有产品的网页输出缺口保持未关闭，后续必须完成整条链路并验证原始网页不会额外发声，不能单独启用新模块作为交付。最新 APK 仍为 0.32.0/code 33，Room schema 28、备份 v23 及原数据不变；无新权限、模块、依赖或 APK。

新增 8 项宿主测试覆盖固定包/序号/冻结采样率、暂停及旧代数据、恶意字段/格式/深度、容量、实际写入后确认、20 轮暂停/定位交错、主文档来源限制及取消擦除。首次编译发现 Android JSONObject 没有桌面版的 keySet 接口，已改为平台支持的 keys 迭代，不引入运行时替代分支。最终构建结果与哈希见 validation.json；Android 测试仅编译，原生静音隔离、工作线程音频采集、唯一输出、音画同步、耳机、锁定与网页残留均为 NOT_RUN。
