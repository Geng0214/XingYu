## 本轮实现

- 五子棋规则：15×15 自由规则，四方向五连或以上获胜，满盘和棋，轮次、越界、重复落子与终局动作校验。全部结果由本地规则计算。
- 翻牌规则：2～12 对随机牌，配对继续、失配展示后换人，双方计分及胜负/平局。完整牌组与可见局面分离；模型只能读取公开状态和双方已经见过的牌面，未见牌不进入请求。
- 约会剧情：地点/主题、用户与角色交替回合、明确结束；取消或格式错误的输出不变成已发生剧情。只保存编码中的已确认进度，实际加密落盘留待存储接入。
- 三种状态采用严格 JSON 格式版本 1，限制字段、数值类型、重复键、深度、总字节数和动作数。编码可重建相同局面；状态列表和公开集合不可变。
- 活动身份校验角色/空间/会话/活动与版本，请求同时持有唯一 token 和冻结状态。开始/提交/暂停/恢复递增版本；旧请求不能覆盖已完成或新一轮的状态。
- 角色回合只接受当前游戏的有限 JSON 动作，不能宣布自己获胜、替用户操作或执行工具。模型配置和当前人设在请求开始时冻结，私聊内容、用户面具、世界书、记忆和工具不自动进入活动。
- 生成协调器使用既有全局互斥和目的地绑定凭据接口。取消、隐私访问版本变化、角色/活动修改等待任务终止再更新；准备事务期间收到取消也会收尾已分配 token。失败的动作保留已报告用量与原始请求输出，已确认局面不变。

- 规则验证包含四方向连线、六连桥接、225 格和棋、非法/终局动作、不变性、隐藏牌序等价观察、失配换人、配对连续行动、计分平局、严格存档校验、中文/emoji 与转义导致的字节膨胀。

- 20 轮执行真实 PlayCoordinator、延迟 Flow 提供器和存储契约替身：部分回复、取消等待、全局互斥、角色/模型修改、重试、正常完成与角色删除，检查旧 token 拒绝、用量与确认局面。不是 Room 或真实服务商验收。
- 额外验证了准备事务期间取消、锁定后解锁的访问版本变化、无关角色编辑、凭据读取失败、非法输出仍记录用量，以及工具调用零执行。
