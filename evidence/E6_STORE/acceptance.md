## 实现与数据边界

- 新增 play_sessions 与 play_requests，保存角色/空间/会话/活动身份、版本、创建/更新时间、局面/剧情、在途 token、模型回合原始输出、状态及冻结用量。完整牌组只在加密存档中保存，模型上下文仍使用可见局面。
- 为 roles(id,spaceId)、chats(id,roleId) 添加唯一索引，活动表通过复合外键核验归属；请求再通过四列外键绑定活动。错误角色、空间或会话不能作为正常外键插入。角色/会话删除在原事务中级联删除所属活动及请求，共享模型配置保留。
- PlayRepository 实现实际 Room 创建、查询、动作、暂停/恢复、删除、请求准备/进度/完成/失败与进程恢复。请求更新 SQL 同时检查角色、空间、会话、活动、请求 token、活动版本和活动请求状态；提交还核对冻结局面、模型版本、上下文与价格。
- 已确认剧情或棋局只接受规则校验后的单个动作。失败的部分 JSON 保留在请求记录中，不能成为剧情。恢复把在途请求标 FAILED/INTERRUPTED，清空活动 token、递增版本，等待显式恢复和新请求。
- 用量单独保留当时价格和服务商已报告计数，缺失计数保持未知。失败动作的已报告用量不会被清零，写入拒绝计数倒退、输出改写、时间倒退和完成后的修改。
- 备份 v24 继续读取 v1～v23，旧格式补空活动表。追加恢复重映射角色/空间/会话/活动/请求/模型历史身份，保留随机牌序与确认剧情，清空在途 token；原数据不覆盖。恢复校验还核对成功请求与当前确认历史，缺少对应回合、跨角色关联、隐藏牌面进入上下文、内嵌 JSON 重复键或过深嵌套均拒绝。
- 每会话最多 32 个活动，每活动最多 2048 条请求；局面编码 128 KiB、单轮输出 64 KiB、上下文 512 KiB，个人备份继续使用既有 32 MiB 总上限。超限明确报错，不截断存档、不删除旧数据。流式 UTF-16 半个 emoji 先等待完整字符，不写成替代字节。
